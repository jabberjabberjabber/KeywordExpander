# Keyword Expander

A tool for processing and expanding image metadata keywords using semantic similarity and LLM validation. Designed for image collections where keywords were generated by a vision-language model without a controlled vocabulary, resulting in similar-but-inconsistent tags across images. The tool groups related tags, infers parent categories and synonyms, and writes them back to image metadata.

## Features

- Extracts existing metadata keywords from images via ExifTool
- Strips color-prefixed compounds (`blue car` → `car`)
- Splits high-dispersion compound keywords into their component words
- Generates semantic embeddings via any OpenAI-compatible `/v1/embeddings` endpoint
- Finds semantically similar keyword candidates using FAISS
- Validates candidate relationships with an LLM — keeps only parents and exact synonyms, not subtypes
- Writes expanded keyword sets back to image metadata
- Checkpoints each pipeline stage to disk so a run can resume after a failure

## How It Works

1. **Extract** — Collects all keywords from image metadata in a directory tree
2. **Clean** — Strips color prefixes (`red cup`, `blue cup` → `cup`); splits compound keywords whose first word appears as a general modifier across many unique bases (e.g. `wooden table`, `wooden floor`, `wooden leg` → `wooden`, `table`, `floor`, `leg`)
3. **Embed** — Sends the deduplicated keyword list to a `/v1/embeddings` endpoint one at a time and indexes the result with FAISS
4. **Candidate map** — For each keyword, finds its nearest neighbours in embedding space below a configurable distance threshold
5. **Validate** — Sends each keyword and its candidates to an LLM chat endpoint. The LLM keeps only candidates that are exact synonyms or parent categories. `dog` → `["animal", "mammal", "canine"]`, not `["poodle"]` (subtype, wrong direction)
6. **Write back** — Adds validated expansions to every image that contains the original keyword, preserving all existing keywords

## Requirements

- Python 3.8+
- [ExifTool](https://exiftool.org/) installed and on PATH
- An OpenAI-compatible server providing `/v1/embeddings` and `/v1/chat/completions` (e.g. llama.cpp server, vLLM, Ollama, LM Studio)

Python dependencies:
```
numpy
faiss-cpu
PyExifTool
json-repair
requests
```

## Usage

```bash
python KeywordExpander.py /path/to/image/directory \
    --api-base-url http://localhost:8080 \
    --embedding-model all-MiniLM-L6-v2 \
    --chat-model llama-3-8b-instruct
```

The `--api-base-url` should point to the server root — do **not** include `/v1`.

### All options

| Argument | Default | Description |
|---|---|---|
| `directory` | *(required)* | Directory to scan for image files |
| `--api-base-url` | `http://localhost:8080` | Base URL for OpenAI-compatible API |
| `--api-key` | `sk-no-key-required` | API key (most local servers don't require one) |
| `--embedding-model` | `all-MiniLM-L6-v2` | Model name for the embeddings endpoint |
| `--chat-model` | `llama-3-8b-instruct` | Model name for the chat endpoint |
| `--max-candidates` | `15` | Max similar keywords to consider per keyword |
| `--similarity-threshold` | `0.64` | FAISS L2 distance cutoff — lower is stricter |
| `--skip-embeds` | off | Skip embedding step; load existing candidates checkpoint |
| `--skip-candidates` | off | Stop after building the candidate map, skip LLM validation |
| `--load-json` | *(none)* | Load metadata from a specific JSON file instead of scanning |

### Resuming a run

Each stage saves a checkpoint file to the target directory:

| File | Created after |
|---|---|
| `KeywordExpander_metadata.json` | Metadata extraction |
| `KeywordExpander_candidates.json` | Embedding + FAISS candidate map |
| `KeywordExpander_expansions.json` | LLM validation |

If a run fails during LLM validation, re-run with `--skip-embeds` to skip straight to validation using the saved candidate map.

If metadata has already been extracted, it will be loaded automatically from the cache on subsequent runs.

## Semantic hierarchy direction

The LLM is instructed to only accept candidates in the **specific → general** direction:

- `"metal"` → `["material", "substance"]` ✓ (metal is a type of material)
- `"metal"` → `["brass", "bronze"]` ✗ (those are subtypes of metal)

This ensures that expansion tags are always broader than or equivalent to the original, so they apply correctly to every image the original keyword appeared in.
